# funymems.cc

Магазин мемных футболок на русском и казахском. React + Vite + Framer Motion.
Бэкенда пока нет: каталог в коде, корзина и заказы — в `localStorage` браузера.

```bash
npm install
npm run dev      # http://localhost:5173
npm run build
```

## Что внутри

- **Конструктор** — свой текст и фото на футболке, перёд и спина отдельно, перетаскивание мышью и пальцем, шрифты, начертание, обводка, поворот, отмена (Ctrl+Z).
- **Двуязычие RU / ҚАЗ** — переключается всё, включая надписи на самих футболках.
- **Тёмная тема** — переключатель в шапке, при первом заходе берётся из настроек системы.
- **Оформление в два шага** — корзина с данными → «Проверьте свои данные» → согласие с политикой → Kaspi Pay (пока имитация).
- **Каталог фотомокапов** — 26 принтов, каждый в белом и чёрном варианте, деление по языку (RU / ҚАЗ).
- **Выбор товара** — крой (классика / оверсайз), цвет (чёрная / белая), размер (XL / XXL), количество.
- **Цены** — классика 15 900 ₸, оверсайз 18 900 ₸. Надбавки за размер и крой правятся в `src/data.js`.
- **Избранное** — своя страница `/#/favorites` и кнопка в нижней панели.
- Таймер дропа, бегущая строка.

## Админ-панель (демо)

Открывается по адресу `/#admin`, пароль `funymems` (задан в `src/components/Admin.jsx`).
Позволяет прямо в браузере: править каталог (название, цену, язык, скрывать товары,
добавлять из `public/tees`), задавать наценку за размер, смотреть заказы и статистику,
создавать промокоды. Всё живёт в `localStorage` этого браузера — **настоящей защиты
и общего хранилища нет**, это панель редактирования витрины, а не бэкенд.

Промокод вводится в корзине (процент или фикс, скидка на сумму заказа).

## Оплата пока фейковая

Kaspi Pay на кнопке — имитация: полей для реквизитов нет, деньги не списываются,
заказ просто создаётся и падает в `localStorage` этого браузера. До владельца
магазина он не доходит — отправлять его пока некуда.

Чтобы принимать реальные платежи, нужен бэкенд: сумму нельзя считать на клиенте,
иначе заказ можно оформить на любую цену через консоль браузера.

## Деплой на Vercel

Vercel понимает Vite сам, отдельной настройки не нужно — импортируешь репозиторий
и жмёшь Deploy. В репозитории лежит `vercel.json`: он фиксирует команду сборки,
добавляет SPA-фолбэк (любой адрес отдаёт `index.html`) и кеширование картинок.

Переменные окружения (если подключаешь Supabase) добавляются в
**Project Settings → Environment Variables**: `VITE_SUPABASE_URL` и
`VITE_SUPABASE_ANON_KEY`. Из `.env` они не подхватятся — его нет в репозитории.

GitHub Pages тоже настроен (`.github/workflows/deploy.yml`) и на Vercel не влияет:
там сайт живёт в подпапке, поэтому workflow подставляет `BASE_PATH`, а Vercel
отдаёт из корня и переменную не задаёт.

## Supabase

Схема базы под архитектуру из ТЗ (заказ → оплата → CDEK → трек-номер →
защищённая ссылка) лежит в **`supabase/schema.sql`**. Выполнить целиком
в Supabase → SQL Editor, скрипт идемпотентный.

Таблицы: `users`, `orders`, `order_items`, `payments`, `shipments`,
`shipment_events`. Плюс функция `order_by_token()` — по секретному токену
из персональной ссылки отдаёт заказ, позиции и историю доставки.

**RLS включён везде, политик для anon нет** — это не забывчивость. Из браузера
в таблицы не залезть; пишет только backend под ключом `service_role`. Иначе любой
смог бы создать себе заказ со статусом «оплачено».

Ключи: скопируй `.env.example` в `.env` и заполни `VITE_SUPABASE_URL` и
`VITE_SUPABASE_ANON_KEY`. **`service_role` в `.env` класть нельзя** — всё с
префиксом `VITE_` попадает в собранный сайт и видно любому.

### Чего SQL не делает

Схема только хранит данные. Отдельно нужен backend (Node / serverless):

- `POST /api/orders` — создать заказ, **пересчитав сумму на сервере**;
- `POST /api/payment/webhook` — отметить оплату (только по вебхуку платёжной
  системы, не по странице «Спасибо»);
- `POST /api/cdek/create` — создать отправление, получить трек-номер;
- `POST /api/cdek/webhook` — принимать смену статусов;
- `GET /api/orders/:secure_token` — страница заказа (или напрямую через
  `order_by_token()` из браузера).

Для этого нужны ключи CDEK, платёжного сервиса и SendPulse — их у проекта пока нет.

## Файлы

| Файл | Что там |
|---|---|
| `src/data.js` | каталог, цены, шаблоны, оба перевода — правится здесь |
| `src/App.jsx` | секции, корзина, оплата, кошелёк, тема, состояние |
| `src/components/Designer.jsx` | конструктор: вкладки, история отмены, загрузка фото |
| `src/components/Tshirt.jsx` | футболка в SVG: силуэт, принт, перенос строк, перетаскивание |
| `src/components/Account.jsx` | кошелёк, заказы, избранное |
| `src/components/Logo.jsx` | логотип-смайл, «ржёт» при наведении |
| `src/styles.css` | тема и переменные светлой/тёмной палитры |

## Темы

Палитра задана переменными в `:root`, тёмная — в `:root[data-theme='dark']`.
Ключевые: `--paper` (фон), `--ink` (текст и рамки), `--surface` (карточки),
`--shadow-c` (жёсткие тени), `--band-bg` (тёмные полосы), `--pill-bg` / `--pill-fg`
(активные чипы). Новый цвет добавляй сюда, а не в конкретное правило.

## Как добавить футболку

Положи два фото в `public/tees/` — `<slug>-w.png` (белая) и `<slug>-b.png` (чёрная),
затем добавь объект в `PRODUCTS` (`src/data.js`):

```js
{
  id: 'slug',
  market: 'ru',        // 'ru' | 'kk' — язык принта, по нему делится каталог
  base: 9900,          // базовая цена; размер добавляет по SIZE_EXTRA
  color: '#e9e7e2',    // подложка карточки
  photos: { white: '/tees/slug-w.png', black: '/tees/slug-b.png' },
  ru: { title: 'Слоган', sub: 'Короткая подпись' },
  kk: { title: 'Слоган', sub: 'Қысқа сипаттама' },
}
```

Конструктор своих принтов рисуется в SVG (`Tshirt.jsx`) и работает отдельно от каталога.
